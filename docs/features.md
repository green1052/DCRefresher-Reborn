# 기능별 구조

미리보기, 글 목록 새로고침, 이미지 차단, 검색처럼 큰 기능에서 고치기 전에 알아야 할 내용을 정리합니다.

## 미리보기

`features/preview`가 모듈과 UI, `core/preview`가 디시 요청·파싱·캐시(1분, quick-lru 25개)입니다.

글을 열 때의 댓글 요청 규칙입니다. 댓글은 쪽마다 요청이라 같은 글을 열고 닫거나 앞뒤 글을 오갈 때마다 받으면 몇 초 만에 요청이 몰려 디시가 IP를 잠시 막습니다(#273).

1. 캐시에 없는 글이고 목록 행에 댓글 수가 보이면(10초 안에 받은 댓글이 없을 때), 본문 요청과 함께 댓글 목록도 요청합니다. 댓글 토큰(`e_s_n_o`)은 갤러리마다 같아서 목록 페이지의 값을 쓰고, 본문을 읽은 뒤 그 글의 토큰·댓글 번호와 맞을 때만 결과를 씁니다. PageUp/PageDown이나 스크롤 끝 휠로 앞뒤 글로 넘길 때는 미리 요청하지 않습니다.
2. 10초 안에 받은 댓글 목록이 캐시에 있으면 다시 받지 않습니다(`COMMENTS_REUSE`). 새로고침 버튼·자동 새로고침·캐시 비활성화는 늘 받습니다.
3. 댓글은 한 쪽에 100개씩 최대 10쪽을 받아 번호(등록)순으로 합칩니다. 디시 API는 1쪽에 가장 최근 댓글을 줍니다. 최신순 보기는 그릴 때 스레드 첫 댓글만 거꾸로 세우고, 답글순은 답글이 많은 스레드부터 세웁니다(`CommentList.tsx`의 `threadParents`). 답글은 어느 순서든 등록순으로 둡니다.
4. 댓글을 그리는 곳(`pullComments`)은 순번으로 늦게 온 옛 목록이 새 목록을 덮지 않게 합니다. 댓글을 받는 새 경로를 만들 때는 이 함수 안에서 기다리게 합니다. 댓글만 받지 못하면 본문은 두고 댓글 칸에 '다시 시도' 안내(`commentsFailed`)를 보입니다. 캐시의 지난 댓글을 보이고 있으면 안내 대신 토스트로 알립니다.

'주소창에 게시글 주소 표시'(`colorPreviewLink`)가 켜져 있으면 미리보기가 글 주소를 기록에 쌓고 닫을 때 쌓은 만큼 뒤로 갑니다. 브라우저 기록이 50개까지라 40칸이 넘으면 새로 쌓지 않고 바꿉니다. 쌓은 글 주소는 브라우저가 방문한 것으로 쳐서 목록 링크가 `:visited` 색이 됩니다. 미리보기로 읽은 글 표시는 따로 저장하지 않고 이것을 씁니다.

댓글·디시콘 쓰기에 쓰는 디시 JS의 값(reCAPTCHA 사이트 키, `_d()` 해독표)은 `core/preview/dcinside-js.ts`에 모읍니다. E2E(Node)도 불러오므로 이 파일은 타입 말고는 다른 모듈을 불러오지 않습니다. 디시 JS에서 값을 새로 옮겨 오면 여기에 두고 실제 디시 E2E의 검사에도 더합니다([테스트](testing.md#e2e-playwright)).

### 본문 HTML 정화

본문 HTML은 `utils/sanitize.ts`에서 DOMPurify로 정화합니다. `<video>`가 든 DOMParser 문서는 Chrome에서 해제되지 않습니다. 그래서 재사용하는 `<template>`에서 `IN_PLACE`로 정화합니다. 파서도 같은 이유로 문서의 video·audio를 지우고 문서를 들고 있지 않습니다.

여기는 **신뢰 경계**입니다. 본문은 남이 쓴 HTML이고 확장 UI와 같은 shadow 루트 안에 들어갑니다. 무엇을 막는지는 네 가지 이유로 갈립니다. 새 속성을 허용하기 전에 어디에 걸리는지 보세요.

- **확장 UI를 흉내 내는 것**: `<style>`(shadow 루트 전체에 걸림), 폼 요소(가짜 입력칸), `popover`·`command` 속성(최상위 층에 가짜 창).
- **확장의 표시를 덮어쓰는 것**: `data-slot`(단축키 막힘 판정, `utils/event.ts`의 `isTyping`), `data-blocked`·`data-*-revealed`·`data-blur-reveal` 등(차단 가림 판정, `core/block.ts`의 `isBlockedHidden`). 본문이 달면 차단한 이미지의 가림이 스스로 풀립니다.
- **미디어 숨기기를 피해 가는 것**: SVG `<feImage>`·`<image>`, `background` 속성. 스텔스 모드의 태그·CSS 숨기기에 걸리지 않습니다. `sanitizeHtml(html, {stripMedia: true})`는 `img`·`video`·`iframe` 등도 막습니다(`NO_MEDIA`).
- **창 바깥을 침범하는 것**: inline `style`은 `KEPT_STYLE` 허용 목록만 남기고 음수 margin은 버립니다. 안 그러면 본문이 창 테두리를 덮습니다.

그 밖에 `<embed>` 유튜브는 DOMPurify가 버리므로 같은 주소의 `iframe`으로 바꾸고, 차단 단어 검사는 HTML이 아니라 `htmlToText`로 뽑은 글에 합니다.

## 글 목록 새로고침

`features/refresh`는 목록을 받아 지금 목록 자리에 넣습니다.

- 주소를 바꾸지 않은 로드는 행 순서가 같거나 새 글이 한 자리에 끼어든 것뿐이면 바뀐 행만 고칩니다(`list.ts`의 `insertionOf`). 그대로인 행은 hover·리스너가 남고 필터를 다시 하지 않습니다. 검색 결과는 강조와 글·댓글 행 짝이 얽혀 늘 통째로 바꿉니다. 작성자 거르기 목록도 같습니다(제자리에서 고치면 검색 모듈이 이어 붙인 행이 밀려난 행으로 지워집니다). 삭제된 글 보존(미리보기의 `archiveArticle`)은 남긴 행의 복제본을 새 목록에 끼워 같이 비교하므로, 원래 행은 제자리에 남습니다. 그 밖에는 목록을 통째로 바꿉니다.
- 자동 새로고침은 목록 표만 파싱하고 받은 tbody가 지난번과 같으면 파싱도 하지 않습니다. 사용자가 한 로드와 검색 결과, 직전 요청이 실패한 다음 새로고침은 문서 전체를 파싱해 페이징 박스도 맞춥니다.
- 자동 새로고침을 건너뛰는 경우: 탭이 보이지 않을 때(숨은 탭 설정 제외), 직전 새로고침 후 2초 안, 이전 요청을 받는 중일 때, 2페이지 이후, 미리보기 창이 열려 있거나 글 보기 페이지의 목록이 화면 밖일 때(창을 닫거나 목록이 보이면 곧바로 받습니다), 목록 위에 마우스·포커스가 있을 때(설정), 사용자가 멈췄을 때. 관리 체크박스를 체크했거나 목록 행의 디시 유저 메뉴가 열려 있으면 주소를 바꾸지 않는 로드는 모두 건너뜁니다. 마우스·포커스와 체크·메뉴는 응답을 받은 뒤에도 다시 보고, 그사이 그렇게 되었으면 받은 목록을 버립니다.
- 탭으로 돌아왔을 때 긋는 읽은 자리 선은 행의 class(`refresherReadMark`)라 목록을 갈아끼우면 사라집니다. 바뀐 행이 있는 로드 뒤에 `title.ts`의 `showMark`가 다시 긋습니다.
- 목록 요청 하나에는 차례 기다리기·응답 머리·본문을 합쳐 30초 제한(`LIST_TIMEOUT`)을 겁니다. 본문이 멈추면 다음 새로고침도 그동안 막히므로 HTTP 기본 제한(60초)보다 짧게 잡았습니다([HTTP](architecture.md#http)).
- 목록 요청이 실패하면 주기를 최대 60초까지 두 배씩 늘리고 한 번 성공하면 원래 주기로 돌아갑니다. 탭 복귀·뒤로 가기·페이지 이동으로 곧바로 보낸 요청도 응답을 받은 뒤 다음 주기를 잡아 실패가 바로 반영됩니다. 새 글 없는 자동 새로고침이 이어지면 주기를 0.5배씩 최대 4배까지 늘리고, 새 글·강제 로드·탭 복귀·목록 위 마우스·키 입력이 되돌립니다(둘 중 긴 주기를 씁니다). 실제 간격에는 0.5~2초가 무작위로 더해집니다.

## 이미지 차단

`features/block`의 이미지 차단은 본문 이미지(`viewimage.php`) 파일의 SHA-256을 차단 목록(`IMAGE`)에 넣고 비교합니다(`core/block.ts`의 `imageHash`·`isImageBlocked`). 값이 해시라 짧은 정규식은 아무 이미지나 걸리므로 옵션의 차단 창은 이미지 항목에 정규식을 고르지 않게 합니다(`entrypoints/options/BlockDialog.tsx`).

- 배경은 이미지 우클릭 메뉴 "이 이미지 차단"을 글 목록·본문 페이지에만 겁니다(`features/block/background.ts`). 누르면 본문 이미지 호스트 권한(`core/pages.ts`의 `IMAGE_HOST_ORIGINS`, manifest의 선택 권한)을 묻고, 탭에 `refresher:blockImage`를 보냅니다. 권한 요청은 사용자 동작 안에서만 되므로 메뉴 클릭 처리기에서 기다리지 않고 바로 부릅니다. 탭에 받는 쪽이 없으면(설치·업데이트 전에 열린 탭 등) 그 프레임에 새로고침 안내를 띄웁니다.
- 크롬은 gall.dcinside.com 문서가 보내는 viewimage.php fetch·XHR 요청에 CORS 헤더를 붙이는 세션 규칙(declarativeNetRequest)을 겁니다. 규칙이 콘텐츠 스크립트와 페이지 스크립트를 가르지 못해 페이지 스크립트의 같은 요청도 헤더를 받습니다. 탭은 `cache: "force-cache"`로 요청해 페이지가 받아 둔 캐시에서 읽습니다. 파이어폭스는 콘텐츠 스크립트가 페이지 캐시를 쓰지 않으므로, 배경이 페이지의 응답을 흘려보내며 구해 둔 해시를 물어 갑니다(`refresher:imageHash`, [Firefox](firefox.md)).
- 다 받은(`complete`) 이미지만 봅니다. 받기 전에 읽으면 확장이 따로 받게 되어 캐시를 쓰지 못합니다. 주소별 결과는 탭에 남겨 두므로 다시 판정할 때 이미지를 또 받지 않습니다.
- 비슷한 이미지(설정의 "비슷한 이미지")는 dHash·pHash 지문으로 비교합니다(`utils/imageFingerprint.ts`). 원본 크기로 디코딩해 JS로 줄이므로 두 브라우저의 지문이 같습니다. 우클릭 차단은 설정과 상관없이 항목에 원본 지문을 늘 같이 넣어 둡니다. 판정할 때는 대상 이미지의 원본과 좌우 반전본 지문을 둘 다 견줍니다.
- 움짤(`<video>`의 mp4, 움직이는 gif·webp)은 정해 둔 시각(0, 0.5, 1.5, 3초 언저리)의 장면마다 지문을 구해 첫 장면은 `similar`, 나머지는 `frames`에 넣습니다. mp4는 문서에 붙이지 않은 `<video>`로 열어 `VideoFrame`의 밝기 평면(Y)을 읽고(두 브라우저가 같은 값을 줍니다), gif·webp는 `ImageDecoder`로 풉니다. 검은 화면처럼 고른 장면은 뺍니다. 한쪽이 정지 이미지면 한 장면만 맞아도, 둘 다 움짤이면 하나 빼고 다 맞아야 막습니다(`isSimilarSet`).
- 움짤은 파일 전체가 버퍼에 들어온 뒤에 봅니다. 일부만 받은 mp4를 읽으면 나머지를 다시 받기 때문입니다. 받는 동안의 이벤트와 반복 재생으로 처음으로 돌아갈 때(`seeked`)마다 다시 봅니다(`core/block.ts`의 `VIDEO_CHECK_EVENTS`). 파이어폭스는 다 받은 뒤 받는 동안의 이벤트 없이 끝나기도 해서 `seeked`가 있어야 합니다. 비슷한 이미지 판정은 표본마다 기억해 두어, 목록과 설정이 그대로면 다시 계산하지 않습니다.
- 디시는 같은 움짤을 mp4(`<video>`)로 보이다가 그리지 못했거나 누르면 원본 gif(`data-src`)의 `<img>`로 바꿉니다. 오른쪽 버튼을 눌러도 바꾸므로 우클릭 차단은 대개 gif 주소로 옵니다. 그래서 `<video>`를 볼 때 두 주소를 짝으로 적어 두고(`core/block.ts`의 `pairedMediaUrl`), 차단할 때 두 파일을 같은 지문의 항목 둘로 넣습니다.
- 지문은 지문이 든 항목이 있고 이미지가 `MAX_PIXELS` 이하일 때만 한 번에 하나씩 구합니다. 디코딩이 해시보다 훨씬 무겁기 때문입니다. 불일치·불포함(`NOT_*`) 항목은 비슷한 이미지로 넓히지 않습니다. 같은 파일은 지문을 기다리지 않고 파일 해시가 나오자마자 막습니다. 파이어폭스 배경도 파일 해시만 물으면 지문 전에 답합니다.

## 검색

`features/search`는 글 목록·본문 페이지에서 돕니다(본문 페이지에도 검색창과 유저 버블이 있습니다). 이어 붙이기는 목록 페이지에서만 합니다.

- 검색 결과가 한 쪽(`#list_num`, 기본 50개)에 못 미치면 다음 검색 구간(`a.search_next`)을 받아 행을 이어 붙이고, 페이징을 마지막으로 받은 구간 것으로 바꿉니다. 받은 쪽은 최대 "다음 검색 횟수"만큼 캐시해 두어, 새로고침 모듈이 목록을 갈아끼운 뒤 다시 이을 때 또 요청하지 않습니다. 작성자 거르기만 하는 목록은 새로고침 모듈이 목록을 갈아끼워도 1쪽의 그 작성자 글이 그대로면 1분(`REUSE_TTL`) 동안 이어 붙였던 행을 그대로 옮겨 옵니다. 검색 결과(`s_keyword`)는 갈아끼울 때마다 다시 받습니다. 결과가 없는 구간의 표에 디시가 붙인 `empty` class는 행을 이을 때 떼고 모듈을 끄면 되돌립니다(그대로 두면 이은 행마다 칸이 250px로 커집니다).
- 디시 글쓴이 검색(`search_name`)은 닉네임만 찾습니다. 아이디·IP로 찾을 때는 목록 주소에 `rf_uid`·`rf_ip`를 얹고 그 작성자가 아닌 행을 CSS로 숨깁니다(`writer.ts`). 주소의 값은 새로고침 모듈도 쓰므로 `core/http/urls.ts`의 `writerFilter`가 읽습니다. 디시가 만든 페이징 링크에는 이 값이 없으므로 링크마다 다시 얹습니다.
  - 아이디: 배경이 갤로그를 받아(`refresher:gallogPage`) 닉네임을 읽고, 그 닉네임의 글쓴이 검색 결과를 아이디로 거릅니다.
  - IP: 닉네임을 모르므로 검색하지 않고 목록을 다음 쪽(`em + a`)으로 넘기며 거릅니다. 디시가 유동 IP를 앞 두 자리만 보이므로 `123.45` 꼴만 받습니다.
- 갤러리 검색창의 종류에 아이디·IP를 더하고, 그것을 고르면 검색 버튼·Enter를 디시 처리기보다 먼저(capture) 받아 막습니다. 유저 버블의 닉네임 줄과 아이디/IP 줄 검색 버튼은 모듈 api `searchUserPosts`를 부릅니다. 닉네임 줄은 디시 글쓴이 검색 그대로, 아이디/IP 줄은 그 검색에 거르기를 얹습니다.
- 거른 목록의 1쪽은 다음 쪽 글을 이어 붙인 것이라, 새로 받은 1쪽에 없다고 지워진 글이 아닙니다. 그래서 새로고침 모듈의 `isWholeFirstPage`(`features/refresh/list.ts`)는 거르기 중이면 거짓을 돌려 삭제된 글 보존을 끕니다.
